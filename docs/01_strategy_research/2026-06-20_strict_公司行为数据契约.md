# Strict 公司行为数据契约

strict 通过版本化研究快照消费公司行为与证券生命周期数据；快照来自现有 Tushare/数据库管道，必须携带来源、as-of 时间与逐事件哈希。快照完整不等于已晋级：仅全历史重放、因子跳变解释和可靠性门槛都通过后，才可标记 `RECONCILED`。

| 事件类 | 最低字段 | 当前处理 |
|---|---|---|
| 现金分红/送配 | `source_event_id, announcement_date, ex_date, as_of_timestamp, cash_per_share, stock_ratio, source_complete, source_reason, event_hash` | 已有来源可标准化；字段缺失冻结持仓 strict 交易。 |
| 配股 | `source_event_id, announcement_date, ex_date, rights_ratio, rights_price, cash_source, as_of_timestamp, source_complete, source_reason, event_hash` | 现金足额即全额认购；资金不足冻结 strict 后续交易，禁止静默部分认购。 |
| 拆股/合股 | `source_event_id, ex_date, split_ratio, as_of_timestamp, source_complete, source_reason, event_hash` | 未覆盖；无法由已知事件解释的复权因子变化冻结。 |
| 退市/现金结算 | `source_event_id, effective_date, settlement_price, settlement_date, as_of_timestamp, source_complete, source_reason, event_hash` | 未覆盖；持仓标的遇到生命周期缺口冻结。 |

达到 `RECONCILED` 的必要条件：所有持仓复权因子跳变均有事件解释、所有事件均可重放现金/股数变化、数据源异常与未知事件均已 fail-closed 留痕，且全历史可靠性矩阵通过。
