# 三个月冠军策略轮动研究实施

## 当前边界

`trusted_champion_rotation_v1` 是独立研究策略，只消费已保存的账户级净值、持仓、市场环境、
财报公告和可交易股票池证据。它不修改 `production.primary_strategy`，不写数据库，不生成订单，
也不启用 Canary。

## 决策规则

- 策略池固定为流动性质量、流动性质量市场门禁、纯流动性防御和流动性分层+B点进攻四条底层路径。
- 63个交易日成本后账户收益决定拟冠军；126日收益、最大回撤和 Calmar 前50%负责确认。
- 126日收益必须为正、最大回撤不得超过20%；单票和单行业权重分别不得超过20%和40%。
- 普通时期要求领先当前策略3个百分点且连续3日第一；财报密集期提高至5个百分点和连续5日。
- 财报密集期由最近5个交易日公告公司数占可交易股票池比例达到10%触发，只使用 `ann_date <= T` 数据。
- 每日检测、每周最后一个交易日才允许正常切换，T日收盘决策、T+1生效，最短持有5个交易日。
- 财报、持仓暴露或执行代理证据缺失时 fail closed；没有合格冠军时回退生产核心策略。

## 研究入口

```bash
python3 scripts/research/run_trusted_champion_rotation.py \
  --source-dir /absolute/trusted_account_backtest_bundle \
  --earnings-announcements /absolute/earnings_announcements.csv \
  --eligible-universe /absolute/eligible_universe.csv \
  --output-dir exports/trusted_champion_rotation/YYYYMMDD_HHMMSS
```

公告文件必须包含 `symbol,ann_date`；股票池文件必须包含 `trade_date,symbol`，或
`trade_date,eligible_universe_count`。输出包含完整决策、轮动净值、63/126日消融对照、季度OOS、
输入哈希、验收门禁和 disabled-shadow 状态。

## 证据解释

研究净值在底层策略账户收益基础上，对策略切换额外扣除双边成本和滑点，能够验证策略选择的
时间因果性，但不能替代逐订单 strict-ledger 重放。因此只要来源账本、公司行为覆盖、T+1守恒、
执行代理或换手证据不完整，晋级验收固定为失败。

历史回测日期不会计入20个真实 disabled-shadow 交易日。只有显式传入
`--shadow-observation-start` 后的新观察日期才参与计数，且执行代理和 strict ledger 必须同时通过。

## 验收口径

- 24个月预热、3个月验证、3个月步长；季度OOS单独输出。
- 基础切换成本采用单边7.5bp和10bp滑点；压力代理采用30bp和50bp。
- 对照包括生产核心、现有 adaptive、纯63日冠军、纯126日冠军、无财报季加严和完整规则。
- OOS年化收益至少20%、回撤不超过20%、正收益季度至少55%、Calmar至少0.25且较基线提升10%。
- DSR至少90%、PBO不超过25%；公司行为覆盖100%，T+1和订单守恒错误均为0。

只有研究、账本和20日真实 disabled shadow 全部通过后，才允许另行申请 enabled shadow。

## v1.1 分阶段升级

策略规则已冻结为 `1.1`，新增以下研究门禁：

- 63日收益转负时禁止切换到新的风险策略；126日回撤达到15%时目标风险降至50%，达到20%时退出至核心回退策略。
- 切换优势必须覆盖双边成本、滑点、预计冲击和安全垫；低市场状态置信度额外提高领先门槛。
- 最近5日市场状态切换达到3次时进入5个交易日冷静期。
- disabled shadow 除20个真实交易日外，至少需要2次有效切换；历史回测日期不计入真实影子天数。

升级治理入口：

```bash
python scripts/research/run_trusted_champion_upgrade.py build-data \
  --start-date 2013-01-01 --dry-run

python scripts/research/run_trusted_champion_upgrade.py audit \
  --current-stage RESEARCH_BACKTEST \
  --evidence /absolute/path/to/evidence.json

python scripts/research/run_trusted_champion_upgrade.py shadow-update \
  --current-stage SHADOW_DISABLED \
  --daily-evidence /absolute/path/to/daily_evidence.json \
  --prior-ledger /absolute/path/to/previous_shadow_ledger.json
```

阶段严格固定为 `RESEARCH_BACKTEST → SHADOW_DISABLED → SHADOW_ENABLED → CANARY_10 → CANARY_25 → CANARY_50 → CANARY_100`。治理工具只生成待人工审批补丁，不修改生产配置、不生成订单、不接入券商API。数据库凭证缺失时生成不可变的 `BLOCKED_DATA_SOURCE` 证据包。

研究报告新增30、60、90、252交易日滚动收益风险、固定规则滚动OOS和账户交易明细换手证据。正式晋级仍要求来源报告明确标记严格账本 `VERIFIED` 和公司行为覆盖100%。

## 正式证据闭环

正式入口新增为：

```bash
CHENYIYUN_DB_URL='mysql+pymysql://...' \
python scripts/research/run_trusted_champion_upgrade.py formal-run \
  --start-date 2013-01-01 \
  --output-dir /absolute/immutable/formal_run_dir
```

`formal-run` 要求启动时Git工作区干净，并一次性冻结评分、价格、财报公告、历史股票池、交易日历、公司行为和证券生命周期。四个底层策略与 `adaptive_market_style` 必须消费同一组快照，并统一使用 strict T+1 raw-open ledger。

账本状态不接受调用方声明，只能由 `trusted_account_evidence_v1` 派生。`strict_ledger_status=VERIFIED` 同时要求：公司行为覆盖100%、生命周期覆盖100%、T+1违规为0、订单守恒错误为0、输入快照哈希有效且运行可复现。任一条件缺失时保持 `PARTIAL_UNVERIFIED`。

正式输出增加容量冲击、拒单、停牌/涨跌停阻断、延迟执行和现金残余诊断。脏工作区或数据库凭证缺失时，入口不会查询数据或启动回测，只生成不可变 `BLOCKED` 证据。
