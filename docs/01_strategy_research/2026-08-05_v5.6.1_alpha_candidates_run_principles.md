# v5.6.1 Alpha 候选运行原则 — H010 / H011 / H012（2026-08-05）

## 状态与目的

v5.6.1 的三个候选（H010 residualized-F1、H011 F1+R2 crowding overlay、
H012 F1 risk-sized）已于 2026-08-04 预注册（参数冻结，
`config/alpha_challengers/h010_residualized_f1.yaml` 等，`parameter_source:
PRE_REGISTERED`，`data_snapshot_sha` 绑定 release 20260803_oos_v4）。本
文档定义它们的**每日运行原则**——诊断输出契约、门禁语义、正式起点——
以及当前阶段的证据资格边界。

**阶段定位（计划 4.x）**：v5.6.1 只积累证据，不产生正式 forward 证据。
Forward Shadow 处于 `PAUSED_AWAITING_V5_5_1`，08-04 包为
`KNOWN_DEFECT_PRESTART_PACKAGE`（不可消费、不计入 E4）。true-blind 重声明
需等待 v5.5.1 + v5.5.2 合并与完整 checklist（`config/strategy_runtime/
forward_shadow_v2.yaml`）。

## 每日诊断输出契约

每日运行

```bash
python3.14 scripts/research/run_alpha_candidate_diagnostics.py \
    [--date YYYY-MM-DD] [--inputs-dir <hermetic 回放目录>] \
    [--output-root exports/formal_evidence/alpha_challengers]
```

输出按候选写入
`exports/formal_evidence/alpha_challengers/<challenger_id>/factor_diagnostics/
alpha_candidate_gates/<signal_date>.json`（schema:
`alpha_candidate_daily_diagnostics_v1`）。输入族为
bars/mcap/basic/industry/labels（与信号包构建器同一 v5.5.1 PIT-quality
fetch；任一族缺失 → `SIGNAL_PACKAGE_BLOCKED`，绝不静默部分运行）。

### H010（residualized-F1）— 每日 OLS 诊断

模型（预注册）：`F1_score ~ 1 + size + liquidity + market_beta +
industry_FE`（最常见行业为基准 dropped，保证满秩；样式列 z-score，
跨度不变）。

输出：`effective_cross_section` / `universe_rows` / `missing_rate` /
`industry_dummy_count` / `design_rank` / `condition_number` / `style_r2`
/ `residual_mean` / `residual_f1_corr`。

**C3_BLOCKED 门禁**（任一生效则该日不产出 residual，绝不截断拟合）：
- 必需列缺失（score / style / industry）→ C3_BLOCKED
- 有效横截面 < `minimum_cross_section: 20` → C3_BLOCKED
- 设计矩阵 rank < 列数（截距 + 3 样式 + industry dummies）→ C3_BLOCKED

### H011（F1 + R2 crowding overlay）— 每日状态解析

输出：`top5_turnover_concentration` / `small_vs_large_20d_rs` /
`state` / `position_multiplier`。规则来自
`config/risk_overlays/r2_crowding_control.yaml`（最严重者优先）：

- `crowding_extreme`（conc ≥ 0.30 **且** rs ≥ 1.25）→ 0.50
- `crowding_elevated`（conc ≥ 0.25 **或** rs ≥ 1.15）→ 0.70
- 否则 `normal` → 1.0

**Fail-closed**：任一输入缺失/NaN → `state: UNKNOWN`、`position_multiplier:
None`、`R2_INPUT_MISSING`——**绝不**默认正常态 1.0（2026-08-04 缺陷的
语义修复，诊断层已生效）。

> **v5.5.1 遗留（已记录）**：生产链路 `build_daily_alpha_signal_package.py:
r2_position_multiplier` 在指示器缺失时仍返回 1.0（文档化的旧行为，未接入
H011 正式运行）。诊断层是 fail-closed 的权威语义；H011 加入正式 Forward
前必须切换生产 overlay 到 fail-closed 版本（与 PR #187 修复后的
`compute_crowding_state` 配套）。

### H012（F1 risk-sized）— 每日权重构造（证据积累）

输出：`selection`（= F1 Top10，波动率**永不**改变选股）/ `weights` /
`sigma_p` / `top2_risk_contribution` / `cash_residual`。契约
（`h012_f1_risk_sized.yaml: portfolio_constructor`）：

- 原始权重 `1 / forecast_volatility_i` → 归一化 → 单调 fair-allocation
  clamp（`single_name_risk_cap: 0.12`，守恒：sum(w) + cash_residual == 1）
- `top2_risk_contribution > 0.30` → `CAP_VIOLATION`
- `sigma_p > portfolio_vol_target: 0.18` → 全权重等比缩放到目标，
  现金残差 = 1 − Σw
- 选中名称缺 forecast volatility → `RISK_INPUT_MISSING`（绝不静默等权）

**正式起点**：`formal_forward_start: NOT_YET_STARTED`。H012 加入正式
Forward 的条件（计划 4.3）：预注册参数完整 **且** PIT covariance 输入
可用；风险模型缺失 → BLOCKED。在此之前每日诊断仅为证据积累，不构成
正式 forward 证据。

## 证据资格边界（全部硬性约束）

- 2025–2026 为 untouched window：**report-only，永不选择**（已消费的
  E0 研究不算 selection）。
- 诊断输出不驱动任何参数变更；参数调整在新 pre-registration 中进行。
- 任何一天的门禁 BLOCKED 不计数为有效 shadow day；同日其他候选照常
  输出（互不抑制）。
- Hermetic 回放模式（`--inputs-dir`）用于回归验证，与生产 fetch
  完全同构（v5.5.1 PIT-quality、fail-closed）。
