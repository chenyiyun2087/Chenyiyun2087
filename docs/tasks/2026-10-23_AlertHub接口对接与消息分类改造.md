# 2026-10-23 AlertHub 消息接口对接与分类改造

## 1. 任务背景与目标

为实现报警监控与业务消息的统一治理，将 CYY（Chenyiyun）系统的所有消息通过独立的消息报警中心 **AlertHub** 进行发送。同时梳理重构系统消息分类：
1. **批量任务**：仅针对执行失败的批量任务进行告警，突出发出时间、任务名称、错误名称/错误详情等关键排障信息。
2. **业务**：重点针对业务进行描述，去掉任务执行细节（如队列ID、重试次数、耗时、脚本路径等），突出业务产出（调仓订单、收益表现、风控健康评级、撮合表现等）。
3. **统一前缀**：所有消息统一增加 `【CYY】` 前缀。

---

## 2. AlertHub 接口架构分析

- **API 路径**: `POST /api/v1/events`
- **鉴权方式**: HTTP Header `Authorization: Bearer <PROJECT_API_KEY>`
- **多租户隔离**: 在 AlertHub `configs/projects.yaml` 中配置 `cyy` 项目及独立 API Key（`cyy-secret-key-123456`）。
- **消息结构**:
  - `title`: 包含 `【CYY】` 前缀的通知标题
  - `message`: 结构化正文内容
  - `severity`: P0 / P1 / P2 / INFO
  - `component`: 组件/任务名称
  - `reason_code`: 错误分类或业务标识（如 `DATA_READINESS`, `ORDERS_READY`）
  - `fingerprint`: 用于 AlertHub 事故聚合与去重的指纹
  - `labels`: 包含 `category: batch_task | business` 等标签
- **投递与降级机制**:
  - AlertHub 采用 Transactional Outbox 机制异步投递至飞书互动卡片。
  - CYY 端具备本地缓冲兜底机制（当 AlertHub 不可达时自动存入 `~/.alerthub/buffer/` 并降级直连飞书），确保业务绝不中断或丢消息。
