# 新浪截图弹窗修复

2026-10-28 的 `sina_picture` 作业 5225 因新浪新增推广模态框遮挡 B/S 标签而失败，未生成图片。Chrome 与 ChromeDriver 均为 156.0.8078.47，浏览器启动探针通过；真实页面已复现 `ElementClickInterceptedException`。

`BSpointChecker.py` 通过模态框自带的 `.SFA-dark-close` 按钮关闭弹窗并等待消失，再操作图表。若弹窗在定位控件后出现，仅在确认关闭该已知弹窗后重试一次点击；未知遮挡继续失败。截图前再次检查，避免把推广页保存为行情图。没有隐藏或改写行情元素，没有新增配置开关。

复核另发现原截图留在各自发布目录，原有逐子目录共享方式不能覆盖发版后新建的日期。将已经声明为运行数据的 `sina/bs_detection/SinaAppBS` 整体接入 canonical 共享规则；发布时保全 checkout seed，再链接到持久源。既有原图按逐文件 SHA 归集，不重新抓取历史行情，也不倒签历史可得时间。新增回归覆盖“发布后创建新日期仍写入持久源”和“保留旧 seed”，待当前截图与识别作业结束后切换服务。

验证：3 项弹窗回归、3 项新浪查询回归及 8 项发布运行时回归，共 14 项通过。真实 000001、600519 两张截图通过：B/S 标签已选中、全屏图表及当日日期可见，推广层已消失。证据保存在持久目录 `exports/batch_audit/20261028_repair/sina_probe/`。

按稳定性修复发布，保留现有策略冻结。后续全量重跑、产出数量和队列终态另记在本日批量验收报告。回滚时恢复上一发布清单 `chenyiyun-prod-20261025-ledger-repair` 并重新加载服务；原始失败记录、已捕获截图及补录数据保留。
