## 失败原因

1. 2026-08-17 至 2026-08-19 的 `alpha_signal_package_seal` 在开发工作树执行，工作树存在未提交变更，Signal Package 的 fail-closed 门禁正确阻断。
2. `candle_diag_scan` 的扫描本身成功，但 verifier 使用了包含后续日期股票的历史分母，造成覆盖率误报；历史补跑第一次缺少基线时还出现过 `expected_rows=0`，现已改为显式验证阻断。
3. package 阻断沿依赖图传导到 2026-08-18 至 2026-08-19 的 alpha precommit 链路，形成后续阻断记录。

历史 `Failed/Blocked` 记录和原始告警未删除：本次核验仍保留 11 条历史失败/阻断记录和 14 条 `task_failed/task_blocked` 告警记录。

## 已实施修复

- `scripts/ops/release_runtime.py`、`scripts/ops/deploy_production_release.py`：发布干净 detached worktree，写入不可变 runtime release manifest；生成物通过共享目录接入，不覆盖开发工作树。
- `scripts/ops/runtime_preflight.py`：worker 启动时校验 release_id、commit SHA、worktree、数据库连通性和 enabled pipeline 脚本注册表。
- `scripts/ops/task_worker_launcher.py`、`scripts/ops/web_console_launcher.py` 和 launchd plist：从 manifest 启动固定 release checkout；开发工作树改动不进入生产 worker。
- `web/app.py`：candle verifier 使用目标交易日 DWD 的去重股票集合，统一 `YYYYMMDD`/ISO 日期；基线缺失返回 `result=BLOCKED`，不再以 0 分母判定成功。
- `scripts/ops/task_worker_service.py`：验证阻断归类为不可自动重试的 `VERIFICATION`。
- `scripts/ops/build_daily_alpha_signal_package.py`：新封装记录 runtime release_id、release root 和 release SHA，并校验发布 commit；SEALED package 仍禁止覆盖。
- `scripts/maintenance/replay_weekly_failed_batches.py`：按依赖顺序提供 `--dry-run`、`--historical-safe`，只对最新失败/阻断项入队，保留封存 package，历史模式不生成订单、不发送成功通知。
- `AShareDataCenter/data_enhancement/akshare_source_sync/service.py`：目标同日 DWD fallback 已由既有提交固定；本次仅增加同日查询回归测试，保留外部仓库其余未提交改动。
