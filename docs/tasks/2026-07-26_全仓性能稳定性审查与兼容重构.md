## 已修复问题

### P0：Web 模块导入产生数据库副作用

此前导入 `web.app` 会立即执行任务状态初始化并尝试连接数据库。现在任务初始化
只在显式 Web/Worker 启动预检中运行；测试、命令检查和 WSGI 模块发现不再隐式
访问数据库。

### P1：数据库连接策略分散

- 新增共享数据库运行时，统一 PyMySQL 连接/读写超时、事务清理和 SQLAlchemy
  `pool_pre_ping`、池大小、overflow 与 recycle 策略。
- Web 的直接连接点统一通过共享工厂创建。
- Web 驾驶舱、通知和候选导出复用进程级 SQLAlchemy 引擎，不再按请求或辅助函数
  重建连接池。
- 密码仍只来自既有环境变量配置，不会进入缓存键以外的日志或报告输出。

### P1：候选导出重复读取元数据

- 将表名校验、表存在性和列集合查询拆到候选导出内部模块。
- 每次候选运行开始时清空缓存，同一次运行内按引擎/表复用结果，避免结构检查
  重复访问 `information_schema`。
- 将风险分类和权重缩放拆为无数据库副作用的纯 DataFrame 变换；旧函数继续作为
  兼容入口。

### P1：调度逻辑与 Flask 路由耦合

- 将任务到 CLI 参数的映射抽成纯函数和显式上下文。
- 将线程创建抽成生命周期模块；运行角色仍由 `web.app` 决定。
- 保留 `_build_task_script_parts` 和 `start_task_scheduler_loop` 兼容入口。

### P2：研究计算弃用警告

已将两个高频 Pandas `groupby.apply` 调用迁移到显式
`include_groups=False`，并在相关系数输入为常量时直接返回缺失值，避免 NumPy
除零警告，同时保持原有 `dropna` 结果语义。

### P2：运行环境和生成物

- 启动预检明确拒绝 Python 3.11 以下版本；夜间 CI 增加 Python 3.14。
- 日期化候选、策略复盘、研究缓存和结果文本默认忽略；已有已跟踪证据不删除，
  不重写仓库历史。
- `SinaBSDetectorBase.py` 的连续异常空白已压缩，代码路径和目录不移动。

## 性能验证方法

真实环境执行前，先安全设置 `CHENYIYUN_DB_URL`，再运行：

```bash
.venv/bin/python scripts/maintenance/audit_mysql_performance.py \
  --output exports/performance/mysql_before.json

.venv/bin/python scripts/maintenance/benchmark_web_endpoints.py \
  --rounds 3 --samples 20 \
  --output exports/performance/web_before.json
```

改造后重复采集，并通过 `--baseline` 比较 Web p95。任何端点 p95 回退超过 10%
都会返回非零退出码。索引只允许依据慢 SQL、查询计划和相同数据规模下的前后结果
添加，并在临时数据库验证迁移和回滚。

## 验收与剩余风险

- 必须通过快速门禁、完整非集成测试、golden regression、发布冻结和凭据扫描。
- 候选 CSV/JSON/Markdown 字段、权重、订单、风险决策和 T+1 日期必须与固定输入
  基线一致。
- 当前未安全注入数据库 URL，因此本文不声称实际 p95 或候选导出耗时改善比例；
  这些数值是合并前环境验收项。
- `web/app.py` 仍包含大量历史路由和 Schema 兼容代码。继续拆分必须在路由快照和
  临时数据库表征测试覆盖后进行，避免把结构整理与业务迁移混为一体。
- 历史导出导致的 2.79 GiB Git pack 需要单独、明确授权的历史清理任务；本 PR
  仅阻止新增日期化运行产物。
