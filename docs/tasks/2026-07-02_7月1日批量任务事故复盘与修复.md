# 2026-07-01 批量任务事故复盘与修复

## 结论

7 月 1 日正式流水线最终完成了评分、候选、影子盘、收益复盘和 K 线扫描，但运行中存在四个真实故障和一个巡检假失败：

1. `sina_picture` 前两次由错误 Python 环境启动，缺少 `pandas`；第三次才在项目环境完成 435 只股票截图。
2. 已被 `adc_bs_detect` 替代的 `db_bs_detect` 仍被旧运行时配置调度，且未传 `--date`，连续失败两次。
3. 21:12 的全量评分随 Web 服务退出而中断，22:49 新 Web 进程接管队列后重新执行；长任务与 Web 生命周期错误耦合。
4. 月度闭环在测试前已经训练、导入并更新 `active_model.json`；测试失败后自动完整重跑，形成两套数据包、六套模型和两次生产指针覆盖。
5. 日终巡检脚本已经提交巡检行，但父进程通过旧连接读取不到新事务，错误记录为 `no_audit_rows`。

## 修复

- `task_registry/pipeline.yaml` 成为唯一调度启用源，遗留任务只保留历史展示能力。
- Web 与队列 worker 分离；worker 使用 MySQL `GET_LOCK` 单实例租约，由 launchd 独立守护。
- 所有子任务固定使用项目 `.venv`，Web/worker 启动执行解释器、依赖、数据库和流水线预检。
- 调度入队显式携带业务日期；截图、OCR、月度模型等增加真实产物校验。
- 仅死锁、连接中断、超时等瞬态错误自动重试；缺依赖、参数错误、测试门禁和产物校验失败直接终止。
- 月度闭环将测试前置，模型指针在所有检查、报告和导入成功后通过临时文件原子替换；计划任务不再隐式 `--force`。
- 日终巡检校验使用独立新连接，并把非计划星期视为合法跳过。
