# 全面稳定性审计与升级暂停

## 结论

- `config/release_freeze/production_stability_hold.json` 继续保持 `PAUSED`。
- 生产发布、模型指针切换、策略 release 激活/回滚、晋级审批和资本扩张均保持硬阻断；只允许明确标记的稳定性 hotfix。
- 稳定性修复已发布到 `chenyiyun-prod-20260904-stability-hotfix-4`，没有引入策略、模型或资本配置升级。

## 审计与修复

1. 月度 BS 模型周期在任何导出、训练、分数导入和指针变更前检查冻结状态；冻结时写入可验证的合法 `SKIP` manifest，避免把暂停误报成失败，也避免产生副作用。
2. `active_model.json` 损坏或非对象时拒绝覆盖；模型指针写入保留原子替换和临时文件清理。
3. stability hold 增加 schema、时间戳、scope 和重复项校验；启动前置在配置损坏时 fail-closed；策略 release 回滚补上冻结门禁。
4. 任务 worker 获取 MySQL 租约改用统一有界连接工厂，连接超时不会无限阻塞 launchd 启动。
5. runtime preflight 支持独立执行，并继续校验 release 身份、代码干净度、依赖、数据库和权威 pipeline。
6. 既有任务队列过期回收、孤立调度关闭、跨日业务日绑定和缺失 benchmark 修复保持有效；历史失败记录不删除、不改写。
