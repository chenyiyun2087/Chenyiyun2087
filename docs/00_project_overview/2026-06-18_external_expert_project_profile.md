# Chenyiyun2087 外部专家评估画像

> 面向对象：量化/投研外部专家  
> 生成日期：2026-06-18  
> 资料范围：本仓库代码、项目文档、任务记录、回测索引和生产使用说明。本文不连接数据库、不重跑回测、不读取外部行情源。

## 1. 执行摘要

Chenyiyun2087 是一个面向 A 股量化研究与日常执行的多模块系统。它不是单一选股脚本，而是围绕“信号采集、全市场评分、策略研究、账户级回测、候选导出、影子盘复盘、Web 运维”形成的研究生产闭环。

当前系统最成熟的主线是：Sina B/S 信号与全市场评分进入 `scoreRank`，经可信全量池策略生成 Top5 候选，再由 `scripts/ops/export_trusted_strategy_candidates.py` 写入候选、股票池、信号和本地订单草案，并通过影子盘和收益评估脚本做生产后复盘。Web 端 `web/app.py` 统一承载任务调度、页面展示、手动补跑和结果校验。

当前生产主推送策略为 `baseline_full_liquidity_detail_vol_position`，风险档位为 `adaptive`，默认 70% 仓位、Top5、账户最多 5 只、10 个交易日持有。`adaptive_market_style` v2.2 保留为市场、行业、量能状态的风控影子对照。旧 `chenyiyunSelected` 策略已被隔离为 Legacy，不再作为当前生产选股主线。

从投研可信度看，项目有明显优点：研究过程留痕充分，已意识到 T 日信号/T+1 执行、未来函数、模型字段历史回填、成本滑点、可成交性和账户级持仓扩散等关键问题；三年评分补齐后做过完整三年 T+1 账户级回测，并据此否定了部分近期高收益策略的长期裸跑外推。

但项目也有必须正视的风险：当前主推策略的近期收益弹性强，但三年裸跑最大回撤仍很深；部分 `bs_model_*` 模型字段存在历史回填和版本穿越风险，不能直接作为可信生产特征；真实券商委托 API 尚未接入，当前是本地订单草案和人工/半自动执行；系统强依赖 MySQL 数据底座和本地任务调度，外部专家需要重点核验数据时点、字段可见性、生产脚本实际参数和最新文档一致性。

一句话画像：这是一个已经从“研究脚本集合”推进到“可运维策略工厂雏形”的个人/小团队量化系统，但仍处在高风险生产前沿阶段，专家评估应重点验证其长期风险控制、数据点时一致性和执行闭环真实性，而不是只看近期收益曲线。

## 2. 项目全景

### 2.1 主要模块

| 模块 | 定位 | 专家阅读重点 |
|---|---|---|
| `sina/` | B/S 买卖点截图、识别、实盘跟踪和模块内回测。 | B/S 信号如何产生、是否稳定、是否依赖图片识别质量。 |
| `scoreRank/` | 全市场评分与 M2-M8 策略研究中台。 | `score`、`opt_score`、`claude_score`、`bs_score_v2`、`bs_consensus_score` 的构造和时点。 |
| `chenyiyunSelected/` | 原聚宽/本地策略迁移与信号生成。 | 当前已与可信全量池主线区分，旧策略生产隔离情况。 |
| `eastmoney/` | 东方财富舆情与辅助数据处理。 | 是否影响候选池、是否只是辅助扫描。 |
| `web/` | Flask 看板、任务中心、股票池、持仓和策略页面。 | 任务调度、手动补跑、结果校验、生产可观测性。 |
| `backtest/` | 可复用通用回测框架。 | 与当前可信策略账户级回测脚本的关系。 |
| `scripts/ops/` | 日常生产、导出、监控、复盘脚本。 | 真实生产链路入口和默认参数。 |
| `scripts/research/` 与根目录研究脚本 | 策略研究、优化矩阵、历史补齐和实验。 | 研究结果是否被生产采用，是否经过三年验收。 |
| `docs/` | 项目规范、策略研究、回测索引、任务记录和提示词库。 | 研究留痕与结论一致性。 |

### 2.2 核心数据流

```text
Sina B/S 截图与识别
    -> bs_detection_results
    -> scoreRank 日频全市场评分
    -> score_rank_daily
    -> B 点增强分 / 综合建议 / M2-M8 研究
    -> 可信全量池策略候选
    -> 本地订单草案 / Web 股票池 / 飞书通知
    -> T+1 影子成交复盘
    -> 生产策略收益评估
```

ScoreRank 的评分并不是一个单分数体系。项目文档和代码共同显示，当前至少有三类主要分数：

| 字段 | 含义 | 评估关注点 |
|---|---|---|
| `score` | 技术总分，来自趋势、突破、量能、相对强弱、流动性等。 | 技术因子是否过拟合近期市场。 |
| `opt_score` | 分类因子优化分，通常约 0-10。 | 上游因子是否点时可得，异常时是否回退为 `score / 10`。 |
| `claude_score` | AI 六维评分，0-100。 | 六维评分是否稳定、是否有解释和覆盖率。 |
| `bs_score_v2` / `bs_consensus_score` | B 点增强和综合建议分。 | 是否含 `bs_model_*` 历史回填字段，可信回测是否剔除模型风险。 |

## 3. 策略体系画像

### 3.1 Sina B/S 信号体系

Sina 体系负责最原始的 B/S 信号采集和识别。典型任务包括 `sina_picture`、`sina_analyse`、`sina_score`、M7 卖出评估和 Sina 实盘快照。它的价值在于提供“市场出现 B 点”的事件流，但研究记录已经显示，B 点本身并不天然等于长期高胜率买入信号。

过程研究中对 2026 年初至 5 月的首次 B 点事件做过分析：B 点后短线有冲高窗口，但 20 日终值收益可能走弱，说明系统更适合做“机会排序 + 交易管理”，而不是“见 B 就长期持有”。外部专家应重点检查 B/S 识别质量、事件去重、B 点后持有标签、样本切分和成交时点。

### 3.2 可信全量池策略

可信全量池是当前生产主线。它从 `score_rank_daily` 的全市场评分出发，加入流动性、B 点增强、行业约束、市场门禁、动态权重、账户级持仓约束等研究迭代，最后收敛到可导出生产候选的策略集合。

当前主推送策略：

| 项目 | 当前口径 |
|---|---|
| 主策略 | `baseline_full_liquidity_detail_vol_position` |
| 风险档位 | `adaptive` |
| 默认仓位 | 70% |
| 候选数 | Top5 |
| 账户持仓上限 | 最多 5 只 |
| 持有期 | 10 个交易日 |
| 执行 | T 日收盘后生成候选，T+1 开盘附近执行 |
| 风控对照 | `adaptive_market_style` v2.2 |
| 执行产物 | 候选报告、CSV/JSON、本地订单草案、飞书通知、影子盘监控 |

需要特别注意：`docs/production_trusted_strategy_usage.md` 和 `web/app.py` 已明确当前主推送为 `baseline_full_liquidity_detail_vol_position`。`docs/00_project_overview/RUNBOOK.md` 中仍存在“主策略为 `adaptive_market_style`”的旧表述，建议后续单独同步文档，避免生产口径误读。

### 3.3 chenyiyunSelected Legacy 策略

`chenyiyunSelected/` 承接原本地化选股、日/周调仓、涨停检查和仓位更新。2026-05-13 的任务记录显示，旧“陈依云精选”策略已标记为 Legacy，任务中心禁止调度和手动运行，旧脚本默认输出改为 legacy 表，避免误写当前核心信号和订单表。

这意味着外部专家评估时不应把 `chenyiyunSelected` 的旧高股息/小市值策略与当前可信全量池主线混为一谈。它更像是历史策略与执行工具链的一部分，而不是当前主要 Alpha 来源。

### 3.4 AShareDataCenter 影子增强源

AShareDataCenter 作为外部策略、板块、周线确认和风险门禁信号源参与影子增强。当前设计原则是 Chenyiyun 主导生产候选，AShare 命中、补位、风险否决等信息在策略订单对照中展示。

研究记录显示，AShare AUTO 近期收益弹性较高但波动更大，双系统路由第一阶段偏保守；周线确认曾过严，v2.1 后从硬剔除改为降权；v2.2 默认 AShare 补位上限 2 只。当前状态更适合作为影子观察和补充信号，不能视为已经完成三年验收的生产主策略。

## 4. 研究演进脉络

### 4.1 B 点增强研究

早期研究围绕首次 B 点事件和有效状态日切片展开，目标是提升未来 10/20 日最大涨幅命中率、收益回撤比和候选排序质量。研究结论指出：

- 当前 `bs_score` 起初更像规则加权器，而不是经过严格训练和概率校准的命中率模型。
- B 点事件的收益路径显示“有冲高机会，但持有期拉长后回撤压力明显”。
- `s_rs`、`s_liquidity`、`s_breakout`、`claude_score` 等对未来冲高更有信息量，单纯提高技术总分不一定有效。
- 样本切分必须 horizon-aware，否则测试段可能没有完整 10/20 日标签。
- `bs_model_*` 模型字段需要 walk-forward 证明点时可得，否则应标为 `model_risk`。

### 4.2 全量池流动性策略

2026-05-12 起，项目从 B 点事件扩展到“全量股票池 + 流动性约束 + 现有评分体系”的可信策略研究。关键迭代包括：

- 全量评分覆盖门槛：单日评分股票数不少于 5000。
- T 日信号、T+1 开盘买入、持有 10 个交易日卖出。
- 默认 Top5 等权，逐步加入成本、样本切分、流动性分层、突破折扣、衍生流动性、动态因子、行业约束、市场门禁。
- 研究中明确区分事件研究和账户级回测，避免把高度重叠的日滚动事件收益直接等同于账户净值。

### 4.3 历史评分补齐与三年验证

2026-06-03 之前，三年窗口主要缺口是 2023-2024 缺评分。随后项目补齐 2023-2024 共 484 个交易日、约 240 万条评分记录，并完成 2023-01-01 至 2026-06-02 的三年就绪检查。

三年 T+1 账户级回测带来一个重要转折：最近一年高收益策略不能直接外推到三年窗口。部分进攻策略在最近一年非常强，但三年最大回撤极深。此后研究方向从“放大进攻策略收益”转向“市场状态门禁、动态仓位、防守影子和账户级风险控制”。

### 4.4 自适应风控与影子盘

`adaptive_market_style` 从单纯三年低回撤口径升级为“近期收益优先 + 长期风险约束 + 日检周切”的风控影子。v2.2 加入 AShare 加权增强、路由缓存、防守态风险叠加和 45%/50%/70%/80% 的目标仓位建议。

生产链路还加入了：

- 影子盘成交监控：`scripts/ops/run_trusted_strategy_shadow_monitor.py` 复盘上一信号日订单在执行日开盘的可成交性、涨跌停风险和滑点。
- 策略收益评估：`scripts/ops/run_strategy_performance_review.py` 每个交易日生成生产策略收益、回撤、候选订单、影子盘和实盘同步状态报告。
- Web 展示：核心精选页展示候选、信号、影子盘和多策略订单对照。

## 5. 当前生产口径

### 5.1 日终流水线

根据生产使用文档和 Web 任务配置，当前核心日终链路为：

1. 等待行情与基础数据就绪。
2. 执行全 A 股评分：`scoreRank/run_daily.py` 或 `scoreRank.cli.run_daily`。
3. 回填当日行业字段。
4. 构建 B 点综合评分建议。
5. 导出可信全量池候选：`scripts/ops/export_trusted_strategy_candidates.py --risk-profile adaptive --write-db --emit-orders --notify-feishu --max-total-positions 5`。
6. 运行影子盘监控。
7. 运行生产策略收益评估。
8. 继续执行 M1/M8、实盘快照等任务。

Web 任务中心中相关任务默认时间：

| 任务 | 默认时间 | 作用 |
|---|---:|---|
| `sina_score` | 21:00 | 全市场 A 股评分。 |
| `sina_bs_consensus` | 21:20 | B 点综合评分建议。 |
| `trusted_strategy_candidates` | 21:25 | 可信全量池候选导出。 |
| `trusted_strategy_shadow_monitor` | 21:28 | 影子盘成交监控。 |
| `trusted_strategy_performance_review` | 21:32 | 生产收益评估。 |
| `sina_bs_image_weekly_cleanup` | 周五 22:05 | 清理上一周 Sina 检测图片。 |

### 5.2 数据落点与执行边界

候选导出脚本会生成本地文件，并可写入：

| 表/对象 | 用途 |
|---|---|
| `chenyiyun.ads_trusted_strategy_candidates` | 可信候选明细。 |
| `stock_pools` / `stock_pool_items` | `TRUSTED_FULL_POOL_TOP5` 股票池。 |
| `chenyiyun.ads_chenyiyun_selected_signals` | 核心精选页展示信号。 |
| `chenyiyun.ads_local_strategy_orders` | 本地调仓订单草案。 |
| `chenyiyun.ads_trusted_strategy_shadow_fills` | 影子成交明细。 |
| `chenyiyun.ads_trusted_strategy_shadow_daily` | 影子盘汇总。 |

当前系统不会直接向券商柜台发送真实委托。它生成的是本地订单草案和通知，真实成交、无法成交、滑点和持仓同步仍需人工或外部流程确认。

## 6. 可信度评估

### 6.1 强项

- 项目明确把可信回测定义为 T 日信号、T+1 执行，避免收盘后特征直接用于当日成交。
- 动态因子权重和自适应策略选择要求只使用 `exit_date < signal_date` 的已完成样本。
- `bs_model_*` 历史回填字段被明确标为高风险，未通过 walk-forward 证明前不作为可信生产默认。
- 从事件研究升级到账户级 T+1 回测，考虑了整数手、成本、持仓期门禁、账户持仓上限和持仓扩散。
- 加入影子盘监控，用真实 T+1 开盘价复盘可成交性、涨跌停风险和滑点。
- 研究记录没有只保留成功样本，也记录了失败策略、无效门禁、过度防守、止损收益损失等负面结果。

### 6.2 主要风险

| 风险 | 当前表现 | 专家需核验 |
|---|---|---|
| 长期回撤 | 主推策略近期强，但完整三年裸跑最大回撤很深。 | 风险档位是否真的在生产中降低回撤，而不仅是报告对照。 |
| 近期收益外推 | 最近 3 个月和半年收益很亮眼，但三年窗口暴露出风格不稳定。 | 分市场状态、行业状态、成交量状态的样本外表现。 |
| 模型字段穿越 | `bs_model_*` 曾有历史回填和版本差异风险。 | 生产候选是否完全避开未点时验证的字段。 |
| 数据补齐口径 | 2023-2024 无历史 B/S 检测批次，只能补齐规则类字段。 | 三年回测中 B 点相关字段的可比性和覆盖率。 |
| 成本滑点 | 已有成本和影子盘滑点监控，但真实交易冲击仍待验证。 | 大滑点日、涨跌停不可成交、流动性恶化日的处理。 |
| 账户执行 | 当前是订单草案，不是真实券商 API。 | 实盘成交回报、撤单、重试、审计链路是否存在。 |
| 数据底座 | 强依赖 MySQL 表、Tushare/本地数据仓和调度进程。 | 数据更新失败、字段缺失、交易日历异常时是否 fail closed。 |
| 文档一致性 | `RUNBOOK.md` 有旧生产主策略表述。 | 当前实际生产参数以脚本、Web 配置和最新生产文档为准。 |

### 6.3 对回测结论的阅读方式

外部专家应把项目回测分为三层阅读：

1. 事件研究：用于因子强弱、信号方向和特征诊断，不等同账户净值。
2. 非重叠或简化调仓口径：用于快速比较策略组合，但样本可能少。
3. 账户级 T+1 回测：最接近生产逻辑，应作为策略能否进入生产的主要依据。

当前项目的正确方向是优先尊重第三层账户级 T+1 回测，特别是三年窗口，而不是只看最近一年或最近 3 个月收益。

## 7. 工程成熟度

### 7.1 已具备的工程能力

- Web 任务中心支持定时触发、手动运行、任务状态、任务锁、历史记录和结果校验。
- 生产脚本集中放在 `scripts/ops/`，研究脚本和维护脚本正在按规范迁移。
- 文档体系已有总览、目录规范、运行手册、策略研究索引、回测索引、生产使用说明和任务记录。
- 关键策略链路有测试覆盖，包括 `test/ScoreRank/`、`test/Sina/`、`test/chenyiyunSelected/`、`test/test_export_trusted_strategy_candidates.py`、`test/test_scheduler_pipeline.py`。
- 候选导出脚本有前置校验、持仓期门禁、持仓数上限、风险档位默认值和飞书通知留痕。
- 影子盘和收益评估脚本输出审计文件到 `exports/`，符合“原始导出留在 exports，人工索引进 docs”的项目规范。

### 7.2 工程债与待完善项

- 生产入口存在 Web 内置调度和历史 `scheduler.py` 两套叙事，最新文档说明 Web 内置调度为当前入口，但部分任务记录仍引用独立调度器，需要统一说明。
- 部分历史脚本仍在 `scripts/` 根目录，目录整理未完全完成。
- `scoreRank`、`sina`、`web` 对 MySQL schema 和本地环境耦合较强，外部复现成本较高。
- README 与 RUNBOOK 中个别生产主策略描述可能落后于最新生产使用文档。
- 真实下单、成交回报、异常重试、撤单和审计尚未形成完整交易系统闭环。
- AI/Claude 评分和外部 AShare 信号的稳定性、成本、失败模式需要进一步工程化监控。

## 8. 风险与开放问题

以下问题不应视为项目缺陷本身，而是专家评估时最应该攻破的边界：

- 当前 70% 主推仓位的最大可承受回撤是多少？投资者是否接受三年裸跑回撤暴露出的尾部风险？
- `adaptive_market_style` 风控影子是否会实际改变仓位和策略选择，还是仅用于人工参考？
- 如果主推策略近期回撤扩大，系统的降仓触发、人工决策和执行路径是否明确？
- 2023-2024 补齐评分与 2025-2026 有 B/S 检测的样本，在特征分布上是否可比？
- B 点增强分中哪些字段完全点时可得，哪些字段只能作为研究标签？
- `claude_score` 的输入、失败回退、覆盖率和版本稳定性如何审计？
- AShareDataCenter 的 `visible_date`、周线确认、风险否决和补位逻辑是否严格点时？
- 影子盘滑点能否代表真实交易冲击，特别是开盘集合竞价和涨跌停附近？
- Web 任务失败时是否会阻断后续候选写库和订单生成，还是可能产生半成品状态？
- 候选导出写入多个表时是否具备事务一致性和可回滚能力？

## 11. 评估结论

Chenyiyun2087 的核心价值不在于某一个“神奇分数”，而在于它已经把 A 股量化策略从信号、评分、研究、回测、候选、订单草案、影子盘、收益评估串成了一条可审计链路。对外部专家而言，这个项目值得评估，也必须严审。

建议专家的第一优先级不是继续优化收益，而是确认三件事：

1. 所有生产特征是否严格点时可得。
2. 当前 `baseline_full_liquidity_detail_vol_position` + `adaptive_market_style` 风控对照能否在样本外真实降低长期回撤。
3. 订单草案到真实成交之间的执行差异是否可记录、可归因、可反馈。

如果这三点通过，项目可以继续向更正式的影子盘/小资金实盘评估推进；如果任一点不能通过，近期高收益都应降级为研究现象，而不是生产 Alpha 结论。
